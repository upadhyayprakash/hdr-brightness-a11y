Why a screenshot can't show you this

Your screen keeps some brightness in reserve above normal white. Apple calls this Extended Dynamic Range. Ordinary pages never touch that reserve. An HDR image can, and the browser lets it.

A screenshot is saved as a normal SDR image, so anything brighter than normal white gets clipped down to normal white. The glow simply isn't in the file. That's also why nobody notices this in design reviews, bug reports or screenshots on Slack. You only see it live, on an HDR screen.

What the logo file says

Read straight from the JPEG's bytes:

Size100 x 100 pixels, grayscale, 15 KB
Embedded color profile13 KB Apple ICC profile: "Rec. ITU-R BT.2100 PQ"
CICP tag9 / 16 / 0 / 1: BT.2020 primaries, PQ (SMPTE ST 2084) transfer, full range
What PQ meansCode values map to absolute brightness, up to 10,000 nits. White in this file is not "page white", it's "as bright as the screen can go".

Most likely an ordinary logo exported from an Apple tool with an HDR color space selected. No one meant to make it glow.

What exists, and what's missing

Developers can already cap HDR brightness, if they think of it:

img { dynamic-range-limit: standard; }

Exists but almost nobody sets it, and it's the developer's choice, not yours.

They can also ask whether the screen can show HDR:

@media (dynamic-range: high) { ... }

Exists but it describes the hardware. It says nothing about what the person looking at it wants.

What no platform offers is a way for a person to say "please don't flash brightness at me", the way prefers-reduced-motion lets them say "please don't animate at me":

/* Option A: levels */
@media (prefers-dynamic-range: standard) {
  img, video { dynamic-range-limit: standard; }
  .hero-video { display: none; }   /* show the SDR poster instead */
}

/* Option B: on/off */
@media (prefers-reduced-peak-brightness: reduce) {
  img, video { dynamic-range-limit: standard; }
}

Doesn't exist Two candidate names, still open for debate.

To see the effect you need an HDR screen (MacBook Pro XDR, recent iPhone or iPad Pro, many OLED phones and HDR monitors) and a browser that renders HDR images (Chrome, Edge or Safari). The toolbar caps use dynamic-range-limit, supported in Chrome and Edge 136+ and Safari 26+. Screen recordings and screenshots will not capture the difference.
